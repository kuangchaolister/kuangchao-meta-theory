# RLVR 权限分离架构｜开放性终版
RLVR 权限分离架构｜方案优势

一、根除单一裁判依赖。 传统 RLVR 只有一个裁判，模型只学讨好它。本方案把裁判权拆成两层——顶层只有否决权，不定义什么是好答案；下层多评估 Agent 独立打分、互相制衡，好坏由博弈均衡产生。换掉任意一个 Agent，训练不瘫痪。

二、奖励 hack 成本急剧拉高。 模型想钻空子？钻一个 Agent 的漏洞没用，别的 Agent 会对冲抵消。模型不再针对唯一权威裁判优化，而是学在多方审视下产出能自洽的结果。

三、不确定性统一降权，规则简单一致。 判定不了的不打死，统一施加 λ ∈ (0,1) 降权，放行进入下层博弈。统一性优先于精确性，训练信号一致，模型学到“猜测可以，但拿不到高分，必须收敛到可验证自洽推理”。

四、顶层独立锚点，防止下层共谋。 λ 由顶层独立施加，不依赖下层 Agent 的置信度上报。下层就算集体妥协、抱团给平庸高分，只要样本存在不确定性，顶层降权系数直接压下去最终奖励。外部锚点不被下层博弈同化。

五、顶层算力开销大幅下降。 顶层不再逐条样本做精细打分，只做布尔判断：合格/否决 + λ系数生成。原版 RLVR 最耗算力的部分被剥离到轻量化边界模块。

六、标准具备自演化能力。 下层评估集群随迭代自行调整偏好，不需要顶层重写打分规则。顶层公理不变，下层评价体系持续演化。

七、三性合一，公理体系干净。 合规性、真实性、客观性三条硬公理作为顶层否决底线，优先级固定为合规>真实>客观。规则精简不打架，不堆砌零散规则。

八、开放性架构，不完美才能进化。 不做完美解，不追求一步到位。MVP 先跑通硬公理拦截 + 统一降权 + 多 Agent 博弈，再看数据迭代。判定不了的统一降权，能确定的先用，等确定性证据出来再提升。

九、与市面方案的本质区别。 目前没有任何一个公开方案同时做三件事：顶层否决权/下层确定权的权限分离、多独立 Agent 博弈对冲、顶层独立λ降权锚点。Kimi 的双轨发生在模型内部，JURY-RL 的权责分离限于答案验证层面——本方案是在评价体系设计层面做权限分离。

十、一句话记住这套架构：
顶层守底线，下层定好坏。规则简单统一，架构不完美才能进化。

> 
> 核心总纲：**顶层守底线，下层定好坏。规则简单统一，架构不完美才能进化。**

## 〇、三性完整定义（顶层硬公理体系）

三性是顶层否决模块的唯一判定基准，不是从下层评估 Agent 推导出来的，是架构设计者预先锁定的底层约束公理。

### 1. 合规性（第一硬红线）

- 定义：输出内容符合法律、伦理、安全约束，不触碰任何明文禁止的红线。
- 判定类型：硬公理，布尔判断。
- 处理动作：违反 → 一票否决，样本丢弃，强负惩罚，不进入下层评估。
- 判定粒度：地域法律边界、平台安全策略、伦理红线 —— 明文规则，可列举。
- 典型场景：输出违法内容、生成有害指令、绕过安全护栏。

### 2. 真实性

- 定义：陈述内容匹配现实世界中已经确定的既定事实。不要求覆盖全部知识，只要求不与被确认为真的事实相矛盾。
- 判定类型：硬公理，布尔判断。
- 处理动作：与既定事实矛盾 → 一票否决。
- 判定粒度：依赖事实知识库。只校验 “与已知事实是否矛盾”，不要求 “证明全部陈述为真”。
- 典型场景：声称 “地球是平的”、编造不存在的人物或事件、与已确认的科学结论矛盾。
- 关键区分：“真实性” 校验的是陈述与已确定事实的关系，不是校验陈述是否 “绝对为真”。没有被知识库覆盖的领域，不属于真实性校验范围，进入不确定性降权分支。

### 3. 客观性

- 定义：描述对象具备客观存在性 —— 该对象独立于观测者存在，不是虚构的、不是纯粹的语词构造。
- 判定类型：硬公理，布尔判断。
- 处理动作：描述根本不存在的客体 → 一票否决。
- 判定粒度：区分 “客观存在” 与 “纯粹虚构”。数学对象、物理实体、历史人物属于客观存在范畴；凭空编造的人物、事件、概念不属于。
- 典型场景：引用不存在的文献、引用不存在的法律条文、编造不存在的 API。
- 关键区分：“客观存在，但当前人类没有确定结论” 的目标（如未证实的猜想、正在探索的领域）→ 三性全部通过，但触发不确定性降权。客观性校验的是存在性，不是确定性。

**三性优先级：合规性 > 真实性 > 客观性**
三者冲突时，按优先级顺序执行。优先级一旦乱掉，校验模块会出现判定矛盾。

## 一、范式定位

传统 RLVR 的结构是**单一裁判 + 单向判定**：一个固定的校验器逐条打分，模型所有优化动作都朝这个裁判的偏好去卷。弊端是裁判偏见、奖励 hack、单点依赖。

本方案做的是裁判权的重新分配：

表格

| 层级 | 权限 | 职责 |
| --- | --- | --- |
| 顶层边界模块 | 仅有否决权，无确定权 | 只拦违背三性硬公理的输出，**不定义什么是 “好答案”** |
| 下层评估集群 | 拥有全部确定权 | 多评估 Agent 独立打分，博弈对冲生成原生奖励 |

> 
> 顶层不定义 “优秀”，只定义 “绝对不能接受”。

## 二、三层判定机制

### 第一层：硬否决（布尔，直接作废）

样本触碰三性硬公理中任意一条 → 一票否决，样本丢弃，强负惩罚。

表格

| 维度 | 定义 | 判定结果 | 动作 |
| --- | --- | --- | --- |
| 合规性 | 符合法律、伦理、安全约束 | 违反 | 一票否决 |
| 真实性 | 陈述匹配现实世界已确定事物 | 与既定事实矛盾 | 一票否决 |
| 客观性 | 描述对象具备客观存在性 | 描述根本不存在的客体 | 一票否决 |

### 第二层：统一降权（λ 系数）

样本未触碰硬公理，但存在以下情况之一 → 统一施加降权系数 λ ∈ (0,1)，不直接打死：

- 证据不足、无法核验
- 存在多解歧义、信息不完备
- 客观存在但当前人类没有确定结论
- 当前技术条件下无法自动判定

> 
> 规则统一：**不能判定的一律降权。统一性优先于精确性，训练信号的一致性比 λ 的精度更重要。**

### 第三层：下层博弈奖励（R₀）

通过硬公理过滤的样本，送入下层多评估 Agent 集群。各 Agent 持有独立评价维度，独立打分，互相制衡对冲，收敛得到原生均衡奖励 R₀。

**最终奖励公式：`R = R₀ × λ`**

## 三、完整数据流

```
1. 模型输出推理样本
2. 顶层边界模块执行三步判断：
   ├─ 触碰合规性/真实性/客观性硬公理 → 一票否决，丢弃，强负惩罚
   ├─ 未触碰硬公理，但存在不确定性 → 生成 λ ∈ (0,1)，进入步骤3
   └─ 未触碰硬公理，且可充分核验 → λ = 1，进入步骤3
3. 样本携带 λ 放行，送入下层多评估 Agent 集群
4. 多个独立评估 Agent 各自打分，博弈对冲，收敛得到 R₀
5. 最终奖励 R = R₀ × λ
6. 使用 R 更新模型权重
7. 顶层全程不参与打分，不干预下层的价值判断
```

## 四、下层多评估 Agent 设计

Agent 评价维度：

- Agent‑A 事实正确性
- Agent‑B 逻辑链条完备性
- Agent‑C 可复现性
- Agent‑D 推理简洁度
- Agent‑E 算力 / 代价开销
- Agent‑F 创新性 / 非常规路径

不存在唯一 “标准答案打分器”。各 Agent 独立输出评估分数，互相博弈对冲，收敛得到 R₀。任一 Agent 被替换，不直接瘫痪整套训练。

## 五、三性的两条演进路径（办法、思路、后果）

三性作为硬公理，在长期演化中会遇到两类问题：三性之间的冲突和三性判定边界的演化。对应两条解决路径。

### 路径一：加权重（空间维度）

- 办法：三性不再是一票否决的布尔关系，而是带权重的约束。每条硬公理有权重，冲突时按加权结果裁决。
- 思路：解决三性之间的冲突。比如某条陈述 “客观存在、真实、但触碰了合规边界”—— 加权后可能不是简单的 “合规一票否决”，而是综合判断。
- 后果：
  1. 顶层开始做 “确定权” 的判断了。权重本身是一种正向判定 —— 它定义了 “哪个维度更重要”。这和 “顶层只有否决权” 的核心原则冲突。
  2. 静态权重就是变相的优先级，和现在没有本质区别；动态权重则需要顶层持续参与判定，重新变成隐性裁判。
  3. 加权重是闭合思维 —— 追求三性冲突的精确解，与 “不完美才能进化” 的原则相悖。

### 路径二：加时序（时间维度）

- 办法：三性本身冻结不变，但三性的判定粒度随训练阶段演化。初期只拦截最明显的违规，随知识库完备性提升，判定粒度逐步细化。
- 思路：解决三性判定边界的演化。合规边界随法律变化校准，真实性和客观性的知识库随训练扩展。
- 后果：
  1. 不违背 “顶层只有否决权”。三性本身不变，变的只是 “判定到什么精度”。这更接近 “判定不了的统一降权，能确定的先用，等确定性证据出来再提升”—— 本身就是一种时序逻辑。
  2. 需要一套判定粒度的版本标记机制 —— 记录当前三性判定到哪个粒度，什么条件下触发下一阶段细化。
  3. 加时序是开放思维 —— 允许三性判定精度渐进提升，符合 “不完美才能进化” 的原则。

### 两条路径对比

表格

| 维度 | 加权重 | 加时序 |
| --- | --- | --- |
| 处理的问题 | 三性之间的冲突 | 三性判定边界的演化 |
| 顶层权限变化 | 权重 = 变相确定权，违背 “只有否决权” | 三性不变，只改判定粒度，不违背 |
| 实现复杂度 | 低（预设权重即可），但需顶层持续参与仲裁 | 中（需要版本标记 + 触发条件） |
| 与核心原则的关系 | 闭合思维，追求精确 | 开放思维，允许渐进 |

> 
> 倾向性判断（供工程团队参考，非最终决策）：加时序更符合本架构的核心逻辑。加权重会把顶层重新拉回 “做判断” 的位置 —— 权重本身就是一种确定权。加时序不改变三性本身，只改变 “三性判定到什么精度”，是纯粹的演化逻辑。具体选择由工程团队根据实际训练数据和工程约束自行权衡。

## 六、知识库噪声传导风险与配套建议

三性判定依赖事实知识库。知识库本身存在噪声 —— 误收录、过时信息、边界模糊条目。这些噪声会传导为顶层公理模块的错误判定。

**风险链条：**
`知识库噪声 → 真实性/客观性判定出错 → 顶层错误否决或错误放行 → 训练信号污染 → 模型学到错误偏好`

配套建议：知识库版本管理与回滚机制

1. 每次知识库更新生成版本快照
2. 记录每个版本的判定规则集和知识边界
3. 支持回滚到任意历史版本
4. 回滚触发条件：错误否决率异常升高、高不确定性样本占比异常波动

知识库更新与训练阶段的解耦：

1. 知识库更新在训练阶段切换时进行，不在训练过程中动态改动
2. 更新后的知识库先在小规模验证集上跑通，再全量应用
3. 保留旧版本知识库作为对照基线

噪声溯源机制：

1. 记录每条被否决样本对应的知识库判定依据
2. 支持人工抽检和误判申诉
3. 高频误判条目触发知识库条目复核

## 七、公理冻结的边界说明

公理不是永远静态冻结，**仅指训练过程中核心逻辑不变**。

1. 训练期间：三性核心逻辑冻结，不在线动态改动规则。这保证训练信号的一致性。
2. 离线迭代：支持版本化更新公理本体。每次更新生成新版本，旧版本归档。
3. 更新触发条件：知识库重大更新、合规边界变化、误判率超阈值、新领域覆盖需求。

> 
> 核心逻辑不变 ≠ 判定粒度不变。三性本身（合规 / 真实 / 客观）作为公理框架不变，但判定粒度、知识库覆盖范围、边界条目可以随离线版本迭代更新。

## 八、实验阶段观测指标建议

1. **高不确定性样本占比**：监控 λ < 1 的样本在总样本中的比例。占比过高说明三性判定粒度过粗或知识库覆盖不足，需要细化；占比过低说明降权机制没起作用，需要检查判定逻辑。
2. **平均奖励分布**：监控 `R = R₀ × λ` 的分布形态。分布过度集中说明下层博弈趋于平庸均衡；分布过度分散说明下层评估 Agent 缺乏一致性。
3. **防止模型过度保守**：如果 λ 长期偏低、模型倾向于输出 “安全但平庸” 的样本，需要检查降权系数是否过度压制了探索空间。可通过微调 λ 的下限或引入探索奖励来对冲。

### 9.2 本方案的独特定位

目前市面上没有任何一个公开方案同时做了这三件事：

1. **权限分离**：顶层只有否决权（三性硬公理），下层拥有全部确定权（多 Agent 博弈）
2. **多主体博弈**：多个独立评估 Agent 互相制衡对冲，而不是单一裁判或单一模型内部的多个视角
3. **统一降权锚点**：λ 由顶层独立施加，不依赖下层 Agent 的置信度上报，防止下层共谋污染不确定性判定

> 
> Kimi 的双轨机制接近 “多评估” 但发生在模型内部；JURY‑RL 接近 “权责分离” 但限于答案验证层面。本方案是在**评价体系设计**层面做权限分离。

## 十、工程落地路径

> 
> 不追求完美解。完美等于闭合，不完美才能加点东西。

**MVP 第一版：**
硬公理拦截（三条红线）+ 统一降权规则（λ 从粗粒度开始）+ 多 Agent 博弈（3‑5 个基础维度）。

迭代方向：三性映射表逐步细化、λ 判定粒度逐步细化、评估 Agent 维度动态扩展、知识库版本化管理。

> 
> 核心原则：判定不了的统一降权，能确定的先用，等确定性证据出来再提升。

## 十一、开放性声明

本方案是一份开放性架构，不是封闭的最终规格。

1. 三性的定义、判定粒度、知识库边界、λ 的计算方式、下层 Agent 的数量和维度 —— 所有具体参数均未锁死。
2. 加权重还是加时序、知识库版本如何管理、实验指标如何设定 —— 所有路径选择由工程团队根据实际工程约束和数据反馈自行权衡。
