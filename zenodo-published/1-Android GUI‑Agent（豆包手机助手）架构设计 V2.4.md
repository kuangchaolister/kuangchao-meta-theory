## 一、整体产品定位

面向安卓端的 GUI 自动化 Agent，通过解析屏幕画面、控件信息，理解界面并完成用户交给的手机操作任务。

- 输入：用户自然语言任务指令
- 输出：手机界面一系列操作动作（点击、滑动、输入文本、返回等）

### 核心痛点汇总

1. Android 系统随时回收 App 进程，内存瞬时状态直接销毁，无法无限长驻后台。
2. MediaProjection：**Android14 + 一次用户授权后可持续持有会话，不需要每帧截屏弹窗；但新建会话必须用户弹窗确认，无法静默后台拉起采集**。
3. 无障碍存在控件识别盲区：Flutter、WebView、Canvas 页面拿不到完整控件节点；存在 TOCTOU 时间‑检查‑使用竞态风险（采样与执行天然存在微小时差）。
4. Android17 引入**高级保护模式（Advanced Protection Mode）**：用户一旦手动开启，非`isAccessibilityTool="true"`标记的第三方外挂 App 会被直接撤销无障碍权限，开关式失效，无过渡期；Google Play 分发政策也持续对无障碍类应用做收紧管控。
5. GUI 场景极易出现**静默业务污染态：系统 API 上报执行成功，但实际点错控件、弹窗干扰，业务目标已经失败，进程完全正常运行**。
6. 多任务可并行提交，但**真实 GUI 硬件资源存在独占约束**；多个任务在推理规划阶段产出互相冲突意图，排队进入执行阶段，会引发业务行为互相干涉，产生视图分裂。

> 设计总原则：
>
> 1. 长任务强制切为**短生命周期分片**；分片结束持久化快照；授权成功后尽量长期持有 MediaProjection 会话，仅后台切出 / 用户主动终止时释放，对抗系统查杀，避免反复弹窗。
> 2. **梅花冲裁作为独立裁决网关，不和业务执行链路混在一起**；资源预算、风险拦截、熔断、审计旁路全部放在网关层。
> 3. 记忆子系统复用 M0 六层记忆系统**手机端裁剪子集**，规避 M1‑M5 范式坑；新增 UI 指纹、双层记忆失效校验。
> 4. LLM 只输出高层语义意图，**禁止直接下发原生点击坐标**；意图经过冲裁网关校验之后，再交由下层采集执行层转换为机器可校验断言。
> 5. 资源区分物理独占资源、可共享资源；推理规划阶段允许多任务并行，GUI 操作执行阶段受独占硬件资源约束。
> 6. 严格三分法：范式固有机理取舍 / 代码实现 bug / Android 载体硬件 & 系统限制；不幻想靠业务逻辑消除底层系统约束。
> 7. 审计事件流区分：**审计旁路只负责事件持久上报，不参与业务逻辑判断；业务 UI 校验回传属于主业务链路，二者严格分开，杜绝概念混淆**。
> 8. 分片幂等性为架构一等约束；不可重入动作在意图层显式标记，网关禁止对该类分片重试。

## 二、五大核心组件总架构

```
[用户输入]
    ↓
【1 LLM意图规划层】输出语义业务意图（非坐标，不含底层校验target）
    ↓
【2 梅花冲裁 · 裁决网关（总仲裁）】
    ├─独占/共享资源令牌管理｜三层任务预算管控｜静态风险分级
    ├─健康探针【兜底】：采集会话、无障碍服务存活状态探测，携带状态版本号
    └─【审计旁路：独立状态‑事件上报通路（只落盘，不参与业务判断）】
    ↓ 通过校验下发分片任务
【3 滚动分片任务引擎】
    ↓
├─→【4 采集&动作执行层】（AccessibilityService + MediaProjection）
│       └─执行层：实时风险复判、TOCTOU加固、状态事件上报（主通路）、机器校验三元组与match_score计算
└─→【5 M0裁剪版三级记忆子系统（瞬时 / 工作 / 持久）】
        └─schema新增：ui_fingerprint、evidence_schema_version、双层记忆失效校验
```

> 双流模型

1. **权限‑状态流（信息数据流）**：屏幕快照、控件树、任务上下文、记忆条目、分片快照、审计事件流、ui 指纹、各类元数据版本号、`match_score`匹配分数、复合校验子项权重与临界标记。
2. **边界‑执行流（能量控制流）**：分片调度、独占 / 共享资源令牌分配、三层预算、超时、熔断、权限校验、任务终止、异常回退逻辑、健康探针兜底探测。

## 三、各模块详细设计

### 1、LLM 意图规划层

职责：接收用户任务、当前屏幕摘要、记忆上下文，**仅输出高层语义业务意图，不生成控件 ID、哈希等底层校验 target**。

```
{
  "task_sub_id":"分片唯一ID",
  "intention":"打开设置-蓝牙页面",
  "semantic_expect":"预期完成之后界面应当出现蓝牙开关",
  "risk_level":"normal/high/dangerous",
  "max_shard_step":8,
  "need_screenshot_verify":true,
  "idempotent":true,
  "non_reenter_note":""
}
```

字段说明：

- `idempotent`：分片一等架构属性，`true`代表可重入重试；
- `non_reenter_note`：当`idempotent=false`，填写不可重入原因，网关禁止对此分片重试。

能力边界：

1. LLM 只负责理解与规划，**本身没有任何执行权限**；所有意图必须过梅花冲裁网关。
2. LLM 可以读取三级记忆，**不能直接修改底层记忆存储；记忆写入请求封装成事件提交冲裁网关，再送入记忆子系统**。
3. LLM 会产生幻觉、错误规划；下游网关 + 执行层多层校验做拦截，不能信任规划层输出 100% 正确。

> ⚠️重要：`semantic_expect`仅为人类可读语义描述；**机器可校验断言不由 LLM 生成，交由采集 & 执行层转换生成**。

### 2、梅花冲裁｜裁决网关【全局唯一总仲裁收口】

> 参考 K8s‑Scheduler、Harness Cordis 内核、Agent 编排契约缺口设计；独立模块，不嵌入规划层或者执行层内部。

1. **双类型资源令牌仲裁**

```
ExclusiveResource = { screen_token, accessibility_bus_token } // 整机物理独占，GUI操作阶段必须持有
ShareableResource = { projection_session_token, ime_context_token } // 可多实例、可上下文切换，推理阶段不需要
```

- **分片两段式执行**
  - 阶段一【并行段，不占用 ExclusiveResource】：LLM 意图规划、记忆读取、网关静态风险校验；允许多个任务同时在此阶段并行运行。
  - 阶段二【独占段，必须拿到 ExclusiveResource】：GUI 真实操作、屏幕采集校验、分片快照落盘。
- 只有进入阶段二才申请物理独占资源；任意一项`ExclusiveResource`被占用，任务进入等待队列；
- `ShareableResource`按需分配，不阻塞推理、记忆读取。
2. **采集会话独立状态机**

```
UNKNOWN → REQUESTING_USER_CONSENT → ACQUIRED
    ├─→ RELEASED（用户主动释放）：任务挂起等待用户重新发起，不进入FROZEN
    └─→ REVOKED_BY_SYSTEM（系统强制回收）：进入FROZEN冻结，必须用户重新授权后任务方可恢复
```

- 分片进入阶段二执行 GUI 操作，前置强制校验：projection 状态必须为`ACQUIRED`，分片才允许执行业务步骤；
- 若处于`REQUESTING_USER_CONSENT / FROZEN`，分片标记「等待采集资源」，**不计入分片 max_shard_step、不计入分片超时**；
- 系统回收 MediaProjection / 无障碍服务被停用，**执行层优先上报携带`state_version`的状态事件（主通路）**；
- 网关健康探针仅做兜底轮询探测，探针间隔必须小于分片等待资源超时上限；探针只处理主通路漏报场景；
- 区分探测结果：`服务彻底禁用（需用户重新授权）`才执行任务 FROZEN 冻结；`临时不可用`仅降级等待，不冻结任务。

> 业务策略：授权成功后尽量长期持有 MediaProjection；仅 App 切后台、用户主动结束任务才 RELEASE 释放。

3. **三层能量带预算 + 累计未匹配度**
- `TaskBudget`：【任务总预算，用户授权阶段确定】全局总步数、总允许耗时；对下层分片预算做硬上限约束；同时配置**不可量化步数独立上限**。

> 每个分片结束之后，网关从 TaskBudget 扣减该分片实际已消耗步数、已消耗耗时；TaskBudget 资源耗尽，直接熔断后续分片，不再调度新分片。

- `ShardBudget`：【单分片预算】分片内最大步数`max_shard_step`、分片超时；
- `StepBudget`：【单步预算】单步执行 + 推理 + 采集最大耗时；

> 全部资源状态变更的`state_version`为**网关统一分配的全局单一单调递增序列号**；执行层上报与探针探测全部共用同一套序列号。网关只处理版本号增大的事件；重复、乱序事件直接丢弃。

- **累计未匹配度定义**
  1. 普通单类校验：执行层返回`match_score: float ∈ [0,1]`，1 完全匹配，0 = 完全不匹配。
  2. `COMPOSITE`复合校验：由多条子校验项`sub_i`组成，每条子项包含`sub_i.score ∈[0,1]`、`weight_i`权重、`marked_critical`布尔标记；
     - 合成：`match_score = Σ(sub_i.score × weight_i) / Σweight_i`
     - 只要任意子项`marked_critical=true`，整体`match_score`强制置为 0。
  3. 无法做量化打分的业务目标：强制设置`requires_explicit_verification=true`；`match_score`赋值`N/A`；**不计入累计未匹配度数值累加，计入独立不可量化步数统计，受不可量化步数上限管控**。
  4. 基础计算：`raw_bias = Σ(1‑match_score)`
  5. 可选开启指数衰减窗口加权：`biased_sum = Σ( (1‑match_score) * λ^(k‑i) )`，给近期偏差更高权重，避免早期历史偏差永久拖累当前任务。

> λ、各类阈值仅定义计算语义，**具体数值由业务实现层配置，架构层不固化硬编码常量**。

- 当累计未匹配度超过任务全局阈值，或不可量化步数到达上限，直接熔断任务；防御 “每一步局部勉强合格，多步累积整体走向错误” 的静默污染路径。
4. **风险分级静态校验 + 执行层二次复判**
- 网关做**static 静态风险分级**（来自 LLM 输出 risk_level）：normal 放行 /high 需要二次确认 /dangerous 直接拒绝；
- 网关下发任务给执行层，**执行层拿到真实控件信息之后做实时敏感度复判；执行层只允许上报风险等级，无权自行决定暂停 / 拒绝动作；高于静态等级的风险，全部回传给网关，由网关决策是否触发用户二次确认**。
5. **机器可校验断言处理**

> LLM 输出仅为`semantic_expect`语义描述；**采集 & 执行层把语义目标转换为机器可校验三元组，附带 match_score 分数回传给网关**

```
{
  "verification_kind":"CONTROL_ID | OCR_TEXT | SCREEN_REGION_HASH | COMPOSITE",
  "verification_target":"机器校验值，控件id/文本/区域哈希/复合子项集合",
  "timeout_ms":3000,
  "requires_explicit_verification":false
}
```

- 网关接收执行层回传的校验三元组与`match_score`；配置 N 次连续不匹配阈值，达到触发任务熔断；N 为业务可配置参数。
- `requires_explicit_verification=true`：代表目标无法自动校验，必须下一分片第一步专门执行验证。
6. **审计旁路（外挂 App 现实约束）**
   审计保证三级：
- `Best‑Effort`：尽力落盘，进程被杀存在丢失风险，用于普通事件；
- `Durable‑Commit`：CRITICAL 事件采用同步事务 fsync 提交后再返回；会拉高网关 P99 延迟，上线必须做性能压测评估；
- `Lost‑Acceptable`：允许丢失的辅助调试日志。

> 边界约束：
>
> - 使用独立 SQLite 文件、独立 DB 连接，开启 WAL 模式；业务库锁死不会连带阻塞审计写入；
> - 外挂 App 舍弃独立 fork 审计守护进程；进程整体被系统 kill，即便`Durable‑Commit`在 fsync 执行中途被杀死依旧存在极小丢失概率；真正硬件级强审计归入远期 OS‑SystemService 版本。
> - 审计旁路只做事件留存；**业务校验结果回传给网关属于业务主链路，不走审计旁路，杜绝伪独立概念混淆**。

> 网关边界约束：网关只能抬高稳态门槛；不能 100% 杜绝 LLM 幻觉、GUI 静默业务污染态，属于范式固有取舍。

### 3、滚动分片任务引擎

核心思想：把完整大任务切割成多个独立短生命周期分片。

> 载体约束：
> ✅支持**分片粒度断点续跑**
> ❌**不支持分片内部指令级断点**：App 被系统杀掉，分片内存内部全部状态丢失，只能回到**已经持久化完成的分片快照继续执行**。
> ✅分片一等属性`idempotent`；`idempotent=false`不可重入分片，网关禁止对此分片重试重放。

#### 分片生命周期

1. 分片接收来自冲裁网关的合法分片任务；先在**阶段一（并行段）**完成 LLM 规划、记忆读取、网关静态校验。
2. 进入**阶段二**，向网关申请`ExclusiveResource`物理独占资源令牌，拿到之后才允许执行 GUI 操作；
3. 分片执行若干步 GUI 操作；**每一步执行层内部先加固 TOCTOU 防御：点击前重读控件树，校验 nodeId/windowId、isClickable，过滤 stale 失效控件**。
4. **TOCTOU 专项调度约束：TOCTOU 校验命中 stale 失效节点时；如果当前分片 idempotent=false，直接熔断任务，禁止任何重试；仅 idempotent=true 的分片允许重新采集界面之后再重试执行。**
5. 每一步完成，采集层生成机器可校验三元组 + `match_score`，结果回传给梅花冲裁网关。
6. 分片到达：max_shard_step / 分片超时 / 阶段性业务目标达成：
   - ①生成分片**完整快照写入 M0 记忆持久层**；产出**分片局部上下文（≠全局任务状态）**；
   - ②释放 `ExclusiveResource`（screen_token、accessibility_bus_token）；`ShareableResource`内`projection_session_token`保持持有（仅 App 切后台或用户主动结束任务才 RELEASE），`ime_context_token`跟随界面焦点一并释放；
   - ③分片局部上下文交还梅花冲裁网关，开启下一轮调度。
7. 异常分支：连续校验不匹配 / 累计未匹配度超限 / 不可量化步数超限 / 资源组 FROZEN → **网关统一触发熔断终止全局任务；分片引擎只上报局部事件，不能修改全局任务状态**。

#### 调度约束

1. 时钟区分：**monotonic 单调时钟用于分片、步骤超时计时（不受 NTP 时间回拨影响）；墙钟时间用于业务界面、UI 时间判断**。
2. 快照规则：**只保存分片执行完毕之后的完整状态；分片运行中途内存状态不落地持久**；进程被杀，分片中途进度全部丢失。

> 权衡说明：分片`max_shard_step`是多重约束下的权衡可调参数：
>
> - 分片越大：被杀时丢失进度越多；
> - 分片越小：分片切换越频繁，会抬升无障碍操作调用频率，更容易触发 Android15 + 系统操作频率告警；
>   该参数需要真机实测调优；业务层可通过分片内插入 pause 停顿，控制操作节奏。

### 4、采集 & 动作执行层（Android 系统载体层）

底层依赖：AccessibilityService 无障碍、MediaProjection 屏幕采集

> TOCTOU 风险两层划分
>
> 1. ✅**可加固消除**：点击前重读 nodeId、windowId，校验`isClickable()`，过滤 stale 失效控件；属于实现层可修复；
> 2. ❌**范式固有无法根除**：快照采集时刻和动作执行时刻永远存在微小时间窗口，只能降低概率，不能完全消除。

能力输出：

- 控件节点树、屏幕位图、OCR 文本；
- 标准化动作：点击、滑动、输入文本、返回、home；
- 返回：API 层面执行结果；机器校验三元组（支持 COMPOSITE 复合子项集合）、每一步`match_score`、实时风险判定结果；携带`state_version`资源状态变更事件，优先上报给网关主通路。

关键逻辑：

1. 接收 LLM 语义`semantic_expect`，**转换输出机器可校验三元组，COMPOSITE 类型按照加权规则计算 match_score；不可量化目标标记 requires_explicit_verification=true，match_score=N/A**；
2. **实时风险复判逻辑**：拿到真实目标控件 resource‑id、文本、所在页面语义，重新计算风险等级；**只允许上报新风险等级，没有权限自行决定动作放行 / 拒绝；风险升高，完整回传给网关做二次确认**；
3. TOCTOU 加固：执行动作前重读控件句柄比对，识别 stale 失效节点；
4. MediaProjection、AccessibilityService 状态变更，优先以事件形式上报网关；健康探针只兜底漏报场景。

> 重要提醒：**系统 API 返回执行成功，不等于业务目标完成；这是 GUI‑Agent 范式层面最高风险来源**。

### 5、M0 记忆系统｜手机裁剪版三级记忆子系统

放弃重型图数据库、大规模向量集群；适配手机本地 SQLite。

#### 三层映射

1. **瞬时记忆（内存）**：当前分片运行时临时上下文，屏幕快照、本轮中间推理。进程被杀全部丢失；**绝不落地持久存储**。
2. **工作记忆（SQLite 高速缓存）**：当前任务分片快照、Episode 事件。分片完成写入；**任务内部记忆写入采用串行提交队列，规避同任务内写冲突**；任务结束可以归档进入持久层。
3. **持久记忆（SQLite 归档层）**：用户长期习惯、历史任务记录；**COW 轻量 diff 快照，支持回滚；全套独立审计变更日志**。

✅schema 字段
每条记忆 Episode 强制携带：

- `evidence：原始控件树/屏幕快照证据片段`
- `evidence_schema_version:int`证据结构版本
- `ui_fingerprint:"App包名:版本号:Activity名"`
- `verified_at:timestamp`网关签发时间戳

✅双层记忆失效校验

1. **第一层快速排除**：检索首先匹配`ui_fingerprint`；App 版本 / Activity 发生变化 → 标记`needs_reverification`送入复核队列，**不能直接供给规划层**。
2. **第二层概率抽检防护**：指纹没有变更的历史记忆，后台按可配置比例做抽检；拉取当前真实控件树哈希比对；抽检发现不一致，则**整批该 Activity 相关记忆送入复核队列**；可配置抽检比例为 0 关闭该层。

> 视图分裂处置补充：比对失败：该 Activity 下全部记忆统一标记`verification_failed`；标记后的记忆禁止供给规划层使用；必须等待用户人工确认之后才可以重置该标记。

✅继承 M0 硬性约束

1. **禁止后台静默 LLM 自动抽取记忆**；所有记忆写入，必须分片任务显式提交，经过冲裁网关校验，附带原始证据；
2. Episode 事件作为一等公民；网关统一签发时间戳，上层业务不可篡改时间；
3. 矛盾记忆不会自动删除，进入复核队列；
4. 记忆向量库与业务知识库物理隔离，杜绝 M4 混库污染。

❌裁剪：完整时序知识图谱重型遍历、大规模 RRF 混合检索；完整版 M0 留在远期服务端方案。

> 固有机理取舍：校验网关依旧依赖 LLM，幻觉依旧有概率落库，只能降低概率，无法彻底根除。

## 四、整套系统运行工况

1. **稳态**
   独占 / 共享资源获取正常；分片两段流转正常；网关风险校验放行；每一步机器三元组校验匹配；累计未匹配度、不可量化步数均在阈值以内；记忆读写正常；审计事件正常落盘；任务稳步向前推进。
2. **偏移态**
   个别分片动作轻微出错；偶发控件识别偏差；分片可以继续运行；**系统不自愈，依赖下一轮机器校验做修正；未触发熔断阈值**。
3. **冲突态**
   分片内部动作意图自相矛盾；多任务并行规划产出冲突 GUI 意图；网关检测冲突告警，任务进入资源等待队列。
4. **视图分裂态**
   两条触发路径：
   ①多个任务在**并行规划段产出互相冲突的 GUI 意图**，排队等待独占`ExclusiveResource`，前后执行的动作互相干涉；
   ②进程重启，瞬时内存全部丢失；持久记忆`ui_fingerprint`检出与当前真实 App 界面不匹配。

> 路径②处置：网关触发界面真实性确认流程；执行层采集当前完整控件树哈希，与记忆内原始证据快照做比对；
>
> - 比对通过则更新该 Activity 下全部记忆的 ui_fingerprint 快照元信息后恢复执行；
> - 比对失败：该 Activity 下全部记忆统一标记`verification_failed`，禁止供给规划层，熔断任务交还用户确认。

5. **静默业务污染态【GUI‑Agent 最高风险工况】**

> 触发条件：
> 1）单分片局部校验勉强合格，**累计未匹配度持续超过阈值 / 不可量化步数超限**；
> 2）TOCTOU 范式时间窗口造成动作命中错误对象；
> 3）记忆绕过双层校验，过期记忆直接供给规划层；
> 进程、API 全部返回成功，但业务目标持续错误向下执行。
> 防护：**单分片 N 次不匹配熔断 + 任务全局累计未匹配度 + 不可量化步数上限三重防护**；外挂版不实现自动自恢复，自动恢复归入远期增值能力。

6. **崩溃态（死・破坏终止）**

> 触发条件：`ExclusiveResource`彻底无法获取；无障碍被 Android17 高级保护模式强制禁用；记忆持久层 IO 完全故障；整套编排链路整体失效；**无本地自动恢复路径，需要用户人工干预**。

## 五、缺陷三分法（范式固有机理取舍 / 项目实现 bug / Android 载体资源限制）

### 🔵范式固有机理取舍（再怎么优化代码也不能根除，只能抬高稳态门槛）

1. LLM 规划幻觉；GUI 静默业务污染态风险；
2. TOCTOU 采样‑执行之间微小时间窗口，无法彻底消除；
3. 记忆校验网关依赖 LLM，幻觉记忆仍有小概率落库；
4. 多任务并行规划可以产出冲突意图，只能靠独占执行段排队约束，不能彻底消灭意图层面冲突。

### 🟢项目实现 bug（编码阶段可以修复）

1. 两类资源令牌分配逻辑漏洞，两段式分片生命周期执行错乱；
2. `match_score`、COMPOSITE 复合校验加权计算、累计未匹配度、不可量化步数统计逻辑错误；
3. 记忆 schema、双层 UI 指纹校验遗漏；
4. 事件`state_version`版本管控失效，出现重复冻结、重复告警；
5. 审计三级保证等级实现错误；
6. 健康探针与主上报通路职责颠倒；
7. 分片`idempotent`属性没有生效，不可重入分片被网关错误重试；TOCTOU 命中 stale 节点未对不可重入分片执行熔断；
8. 执行层越权做业务决策，绕过网关做风险放行 / 拒绝；
9. 分片引擎修改全局任务状态，破坏网关全局状态唯一收口约束；
10. 视图分裂态路径②检出不匹配之后，缺少整批 Activity 记忆比对‑更新‑熔断处置链路。

### 🟡Android 载体 & 系统限制（外部硬约束，外挂 App 无力改变）

1. MediaProjection 新建会话必须用户弹窗确认；授权后可持续持有；系统可随时回收会话；会话中途被系统回收属于可观测、有状态机、可兜底重试的工况，不是范式固有缺陷。
2. App 进程随时被系统查杀；分片内存瞬时状态丢失；仅分片完成快照可以恢复。
3. Flutter/WebView/Canvas 无障碍控件识别盲区。
4. Android15+ AOSP 监控无障碍操作频率；可通过分片步数、pause 停顿控制操作节奏缓解，属于实现层可控旋钮，需要真机标定。
5. Android17 高级保护模式：用户手动开启后，非`isAccessibilityTool="true"`第三方 App 开关式失去无障碍权限，无过渡期。
6. 第三方外挂 App 拿不到系统签名；无法后台无弹窗截屏；无法实现独立进程审计守护进程。

## 六、重构备选方案分级标记

### ✅上层封装（外挂 App 版本，可直接做，不改变整体架构）

1. MediaProjection 完整状态机；分片前置`ACQUIRED`校验；区分主上报通路 + 探针兜底；事件携带`state_version`防重复乱序。
2. LLM 输出语义描述，执行层转换机器可校验三元组；COMPOSITE 复合校验加权打分；区分可量化 / 不可量化目标；N 次不匹配 + 任务全局累计未匹配度 + 不可量化步数三重熔断。
3. 实现`ExclusiveResource / ShareableResource`整套资源组令牌仲裁；分片两段式生命周期；推理阶段允许多任务并行。
4. M0 裁剪记忆：ui_fingerprint 第一层过滤 + 抽检第二层防护；任务内部记忆写入串行队列规避写冲突；视图分裂路径②比对失败整批标记`verification_failed`。
5. 三层预算模型；TaskBudget 分片结束扣减消耗；分片 / 任务两级阈值，配套不可量化步数独立上限。
6. 执行层增加实时风险复判，只上报风险，网关统一决策；TOCTOU 加固，命中 stale 节点对`idempotent=false`分片强制熔断禁止重试。
7. 审计旁路独立 SQLite+WAL，三级审计保证等级；外挂舍弃独立守护进程。
8. 分片一等属性`idempotent`；不可重入分片禁止重试。
9. 网关增加健康探针探测载体服务存活；全局任务状态变更唯一收口网关。
10. 补齐完整六工况；视图分裂路径②完整处置链路。

### ⚠️需要改动内核（远期 OS‑SystemService 原生版本才考虑，外挂版本不碰）

1. ROM 系统签名绕过 MediaProjection 新建会话弹窗；
2. 真正分片内部指令级断点，进程被杀保留分片中间内存状态；
3. 独立进程审计守护进程，硬件级不可丢失审计；
4. 系统层全局 GUI 资源抢占原语。

### ⚪概念方案（仅理论构想，现阶段不落地）

1. GUI Agent 失败惯性自动自恢复机制。

# 附录 1｜狂潮・八步正向分析归档

> 元理论版本：v1.0‑public
> 说明：纯架构语义定义，阈值、衰减系数、权重仅规定计算语义约束，**具体数值交由业务实现层配置，架构层不固化硬编码常量**。

## 1｜模块边界定格

### 分析对象集合

1. **LLM 意图规划层**：输入用户任务、屏幕摘要、记忆上下文；只输出高层语义意图 JSON；禁止输出底层控件坐标；无执行权，无直接记忆写权限。输出字段包含分片一等属性`idempotent`、`non_reenter_note`、`semantic_expect`（仅人类可读语义，不做机器校验）。
2. **梅花冲裁・裁决网关【全局唯一总仲裁收口】**
   - 资源令牌管理：`ExclusiveResource`{screen_token,accessibility_bus_token}；`ShareableResource`{projection_session_token,ime_context_token}
   - MediaProjection 状态机：`UNKNOWN→REQUESTING_USER_CONSENT→ACQUIRED→RELEASED/REVOKED_BY_SYSTEM→FROZEN`
     - `RELEASED`：用户主动结束，任务挂起等待用户重新发起，不进入 FROZEN
     - `REVOKED_BY_SYSTEM`：系统强制回收，进入`FROZEN`，必须用户重新授权后任务方可恢复
   - 三层预算：`TaskBudget / ShardBudget / StepBudget`；每个分片结束之后，网关从 TaskBudget 扣减该分片实际已消耗步数与耗时；TaskBudget 耗尽则熔断后续分片。
   - 全部资源状态变更的`state_version`为**网关统一分配的全局单一单调递增序列号**；执行层上报、健康探针探测全部共用同一套序列号。
   - 累计未匹配度；普通 / COMPOSITE 复合校验加权规则；不可量化步数独立统计；
   - 风险管控：网关静态风险分级；执行层仅上报风险，无权决策；`state_version`单调版本号，抑制乱序 / 重复事件；
   - 审计旁路：三级保证等级`Best‑Effort / Durable‑Commit / Lost‑Acceptable`；外挂 App 舍弃独立审计守护进程；审计仅做事件留存，**不参与业务判断，业务校验回传走主链路**。
3. **滚动分片任务引擎**
   - 分片两段生命周期：【阶段一 并行规划段（不占用 ExclusiveResource）】 /【阶段二 独占 GUI 执行段】
   - 断点约束：**仅分片粒度断点续跑，不存在分片内部指令级断点**；进程被杀，分片内存中间状态全部丢失；仅分片执行完毕快照可恢复。
   - 分片一等属性`idempotent`；`idempotent=false`不可重入分片；TOCTOU 命中 stale 节点，不可重入分片直接熔断禁止重试。
   - 快照规则：**只持久化分片完成快照，分片运行中途内存绝不落盘**。
4. **采集 & 动作执行层**
   - 底层依赖：AccessibilityService、MediaProjection；
   - TOCTOU 两层区分：可加固（动作前重读 nodeId/windowId/isClickable 过滤 stale 控件）；范式固有（采样与执行存在微小时间差，无法彻底根除）；
   - 职责：把`semantic_expect`语义描述转换为机器可校验三元组；计算 match_score；执行 GUI 动作；上报控件 / 屏幕结果、风险提示、资源状态变更事件（主上报通路）。
5. **M0 裁剪版三级记忆子系统（手机 SQLite，舍弃重型图数据库）**
   - 三层存储：瞬时记忆 (内存，进程被杀丢失)｜工作记忆（SQLite 高速缓存，任务内部串行写队列）｜持久记忆（SQLite 归档层，COW 轻量 diff 快照）；
   - Episode 强制字段：`evidence`证据片段、`evidence_schema_version`、`ui_fingerprint`、`verified_at`网关签发时间；
   - 双层失效校验：第一层`ui_fingerprint`快速过滤；第二层可配置概率抽检；Activity 界面变动做**整批记忆复核**；比对失败标记`verification_failed`禁止供给规划；
   - 硬性约束：禁止后台静默 LLM 自动抽取记忆；记忆写入必须经过网关校验，携带原始证据；记忆向量库与业务知识库物理隔离。

### 外部边界｜不属于本系统

1. Android 系统载体：Activity 生命周期、进程 LMK 查杀、MediaProjection 授权弹窗、无障碍服务管控、Android15 操作频率监控、Android17 高级保护模式；
2. LLM 基座本身幻觉、模型能力上限；
3. OS‑SystemService 系统原生版本全套内核改造；
4. 独立进程硬件级强审计守护进程；
5. GUI Agent 自动失败惯性自恢复（远期增值能力，外挂版不实现）。

> 边界原则：严格区分三类问题：🔵范式固有机理取舍 / 🟢项目实现 bug / 🟡Android 载体硬约束。

## 2｜两套完整链路拆解（权限‑状态流｜边界‑执行流）

### 权限‑状态流【信息数据流】

流转实体：用户任务文本、分片意图 JSON、资源令牌、state_version 版本号、屏幕快照、控件树 OCR、机器校验三元组、match_score、累计未匹配度、不可量化步数、Episode 记忆条目、ui_fingerprint 证据、分片快照、审计事件流。

1. 用户输入 → LLM 意图规划层，产出仅语义意图，携带`idempotent`属性；
2. 意图送入梅花冲裁网关；网关做静态风险分级；进入分片调度；
3. 分片阶段一（并行规划段，不拿独占资源）：读取 M0 记忆子系统，做规划推演；
4. 进入阶段二，向网关申请`ExclusiveResource`；资源拿到，下发任务至采集 & 动作执行层；
5. 执行层：
   - 将`semantic_expect`转换机器可校验三元组；
   - TOCTOU 加固前置校验；执行 GUI 动作；
   - 计算 match_score；
   - 实时复判风险等级，**仅上报，不做放行 / 拒绝决策**；
   - 资源状态变更携带全局`state_version`走主通路上报网关；
6. 校验结果、match_score 回传给梅花冲裁网关；网关更新累计未匹配度、不可量化步数；每个分片结束扣减 TaskBudget 消耗；执行熔断判断；
7. 分片达成结束条件：生成分片完整快照，写入 M0 记忆子系统；
   - 释放`ExclusiveResource`；`projection_session_token`尽量长期持有；`ime_context_token`随焦点释放；
8. 异常分支：
   - TOCTOU 命中 stale 节点 && `idempotent=false` → 网关直接熔断，禁止重试；
   - 累计未匹配度超限 / 不可量化步数超限 / N 次连续校验不匹配 → 网关统一熔断；
   - 视图分裂‑路径②：重启后记忆指纹不匹配；采集真实控件树比对；比对通过整批更新 Activity 记忆元信息恢复执行；比对失败整批标记`verification_failed`，熔断交还用户；
9. 记忆写入链路：所有记忆变更事件提交网关校验，携带原始证据，再送入记忆子系统；任务内部记忆写入走串行提交队列；
10. 审计旁路：事件分流；CRITICAL 事件支持 Durable‑Commit 同步 fsync；普通事件 Best‑Effort；外挂版进程被杀内存未刷盘事件允许丢失；审计事件**不参与业务逻辑判断**。

### 边界‑执行流【能量控制流】

流转实体：资源令牌分配、分片两段调度、Task/Shard/Step 三层预算、monotonic 单调时钟（超时计时）、墙钟时间（UI 业务时间）、状态机流转、熔断、冻结、健康探针兜底探测、风险决策、任务终止。

1. 时钟强制区分：`monotonic单调时钟`用于分片 / 步骤超时，不受 NTP 回拨；墙钟时间用于界面业务判断；
2. MediaProjection 状态流转严格区分`RELEASED`/`REVOKED_BY_SYSTEM`不同转移语义；
3. `state_version`网关全局单一单调递增序列号；网关丢弃版本不递增的重复乱序事件；
4. 资源管控：`ExclusiveResource`整机全局互斥；阶段一并行规划段不占用；阶段二 GUI 执行必须申请拿到；`ShareableResource`按需分配，不阻塞推理；
5. 健康探针定位：**仅兜底探测；主状态信号来自执行层上报；探针间隔必须小于分片等待资源超时上限；区分彻底禁用 vs 临时不可用**；
6. 预算管控：TaskBudget 为全局硬上限；分片结束扣减消耗；累计未匹配度、不可量化步数做全局熔断防护；
7. 风险决策：网关做静态分级；执行层只上报风险；高于静态风险等级全部回交网关，网关决定是否二次确认；**执行层无业务决策权限**；
8. 熔断与终止：**全局任务终止、全局资源状态变更，唯一收口梅花冲裁网关**；分片引擎、执行层只产出分片局部上下文，禁止修改全局任务对象；
9. M0 记忆：写入必须网关校验；双层 ui_fingerprint + 抽检；Activity 不匹配整批标记`verification_failed`；任务内部串行写队列规避同任务写冲突。

## 3｜六条动态契约核验

契约：信息配时序｜控制配轮询｜数据配权限｜一致就向前｜能量带定义｜状态要报备

1. **信息配时序 ✅部分满足，存在固有时序窗口**
   - 分片快照只在分片执行完毕落盘；进程被杀，分片中间内存状态全部丢失；存在内存视图 vs 持久快照视图不一致窗口；
   - M0 记忆双层校验，`ui_fingerprint`+ 抽检，识别界面变更带来的记忆‑现实视图差；
   - 视图分裂两条路径都有检测 + 处置链路；
   - 限制：LLM 规划、记忆抽取依旧会产生时序‑事实错误，属于范式固有，架构只能检测处置，不能从源头消除。
2. **控制配轮询 ✅补齐**
   - 资源拆分为`ExclusiveResource`与`ShareableResource`；分片两段式：规划段并行，GUI 执行段强制拿独占令牌；
   - `state_version`全局序列号，处理事件乱序重复；健康探针做兜底探测；
   - 多任务并行规划可以产出冲突意图，通过独占执行段排队约束，降低视图分裂概率；
   - 风险：上层业务调度依然可以提交大量冲突任务，架构只能在网关层拦截，无法阻止上游提交。
3. **数据配权限 ✅补齐**
   - LLM 规划层禁止直接执行动作、禁止直接写底层记忆；全部请求提交网关校验；
   - 执行层只能上报风险，**无权做放行 / 拒绝的业务决策**；
   - M0 记忆：记忆写入必须网关校验，附带原始证据；记忆库与业务知识库物理隔离；
   - 限制：外挂 App 无法阻止 Android 系统层面篡改本 App 私有存储；底层操作系统权限不在系统管控域内。
4. **一致就向前 ⚠️部分满足（范式固有缺口）**
   - 引入机器可校验三元组、match_score、累计未匹配度、不可量化步数；校验失败可以熔断任务；
   - M0 记忆做指纹 + 抽检识别记忆与现实界面不一致；检出后熔断 / 送入复核队列；比对失败整批标记`verification_failed`；
   - ❗无法做到 “全链路事实一致性自动修复”：LLM 幻觉、TOCTOU 微小采样‑执行时差、记忆幻觉落库，属于范式固有取舍；架构只能检测 + 终止任务，不能自动修正错误事实。
5. **能量带定义 ✅补齐**
   - 三层预算模型：TaskBudget（全局硬上限，分片结束扣减消耗）、ShardBudget、StepBudget；
   - 新增：累计未匹配度、不可量化步数独立统计；分片 max_shard_step；monotonic 超时计时；
   - 资源状态机 FROZEN 冻结、等待资源不计入分片步数与分片超时；
   - 分片一等属性`idempotent`，对不可重入分片做重试禁止；TOCTOU‑stale 节点命中熔断规则；
   - λ、阈值、N 等**仅定义计算语义，架构层不固化数值，交由业务配置层实现**。
6. **状态要报备 ✅补齐（区分业务主链路 / 审计旁路）**
   - 资源状态变更优先走执行层主上报通路，携带全局`state_version`；健康探针仅兜底；
   - 审计旁路独立 SQLite+WAL；三级保证等级；CRITICAL 支持 Durable‑Commit 同步 fsync；
   - 明确外挂 App 现实约束：进程整体被杀，内存未刷盘审计事件存在丢失风险；硬件级强审计归入远期 OS 原生版本；
   - 审计旁路只留存事件；**业务校验、风险决策回传走业务主链路，审计绝不参与业务判断，杜绝伪审计**。

> 契约总评：六契约缺口均已识别并给出架构层面的防护机制；**部分缺口受限于范式机理、Android 外挂载体，只能抬高稳态门槛，无法彻底根除**。

## 4｜五种运行工况判定（元理论标准五工况，新增崩溃态）

1. **稳态**
   资源令牌获取正常；分片两段流转正常；网关风险校验放行；机器校验匹配；累计未匹配度、不可量化步数全部在阈值以内；M0 记忆双层校验通过；审计事件按等级落盘；任务稳步向前推进。
2. **偏移态**
   个别分片动作轻微出错；控件识别偶发偏差；分片可以继续执行；**系统不自愈，依赖下一轮机器校验做修正；未触发熔断阈值**。
3. **冲突态**
- 分片内部动作意图自相矛盾；
- 多个任务并行规划产出互相冲突 GUI 意图，排队等待`ExclusiveResource`；网关告警，任务进入等待队列；
- M0 记忆检出同 Activity 多条互相矛盾记忆，送入复核队列；

> 不会直接崩溃，但业务目标受干扰。

4. **视图分裂态**

> 路径①：多任务并行规划产出冲突意图；排队进入独占执行段，前后动作互相干涉；
> 路径②：App 进程重启，瞬时内存丢失；持久记忆`ui_fingerprint`检出与真实界面不匹配；
> 处置：网关触发真实性比对；比对通过整批更新 Activity 记忆元信息恢复执行；比对失败整批标记`verification_failed`，熔断交还用户确认。

5. **静默业务污染态【GUI‑Agent 最高风险工况】**
   触发来源三选一：
- 单分片局部校验勉强合格，**累计未匹配度持续超标 / 不可量化步数超限**；
- TOCTOU 范式固有微小时间窗口，动作命中错误对象；
- M0 记忆绕过双层校验，过期记忆直接供给规划层；
  现象：API 全部返回执行成功，进程完好运行，但业务目标持续错误向下执行；
  防护手段：单分片 N 次不匹配熔断 + 累计未匹配度 + 不可量化步数上限三重防护；

> 外挂版：只做终止熔断；**不实现自动自恢复，自动恢复归入远期增值能力**。

6. **崩溃态（死・破坏终止）**

> 触发条件：`ExclusiveResource`彻底无法获取；无障碍被 Android17 高级保护模式强制禁用；记忆持久层 IO 完全故障；整套编排链路整体失效；**无本地自动恢复路径，需要用户人工干预**。
> 区分：`RELEASED`用户主动释放不属于崩溃态，仅任务挂起；只有`REVOKED_BY_SYSTEM`系统强制回收且无法重新授权、底层存储 IO 故障才进入崩溃态。

> 工况区分：范式机理缺陷 / 实现 bug / Android 载体缺陷；载体故障直接进入崩溃态；范式缺陷表现为偏移‑冲突‑视图分裂‑静默业务污染；实现 bug 会放大各类工况触发概率。

## 5｜旺‑生‑休‑克‑死 五类组件耦合

1. **旺｜双向增益**
   - LLM 意图规划层 ⇔ M0 裁剪记忆子系统：读取历史记忆提升规划质量；分片执行产出新证据快照，反哺记忆库；

     > 架构约束：**全部记忆写入强制网关校验，主动抑制无管控旺耦合，防止幻觉不受约束的自我强化**。
   - 采集执行层 ⇔ 梅花冲裁网关：采集层回传校验结果、资源状态；网关下发资源令牌、熔断、风险决策。
   - 分片任务引擎 ⇔ M0 记忆：分片完成产出快照落盘；快照作为续跑输入，开启下一轮分片。
2. **生｜单向供给**
   用户输入 → LLM 意图规划层 → 梅花冲裁网关 → 分片任务引擎 → 采集执行层；各类屏幕、控件、OCR 原始信息单向流入推理链路；记忆 Episode 证据单向存入 M0 存储；审计事件单向流入审计旁路。
3. **休｜休眠闲置**
- 分片任务引擎：无任务分配，分片实例休眠；
- 采集 & 动作执行层：没有拿到`ExclusiveResource`，硬件采集链路休眠；
- M0 记忆子系统：无读写请求，存储层休眠；
- 健康探针：按间隔轮询，未探测事件时休眠；

> 休眠定义：组件实体存在，本周期无交互，不等于销毁。

4. **克｜约束压制（不会直接摧毁组件，抬高故障触发门槛）**
- TaskBudget 全局预算压制分片 / 单步最大开销；分片结束扣减消耗；累计未匹配度、不可量化步数压制长任务错误累积；
- `ExclusiveResource`独占令牌压制多任务同时做 GUI 操作，缓解视图分裂；
- M0 双层记忆校验压制过期记忆直接流入规划层；
- 网关风险分级、执行层上报机制压制越权动作；
- Android 载体约束：进程查杀、MediaProjection 授权弹窗、无障碍管控，对整套系统形成外部压制。
5. **死｜破坏终止（流转直接断裂）**
- Android 载体层面：无障碍被高级保护模式禁用、MediaProjection 会话被系统永久回收、SQLite 记忆库 IO 故障；直接进入崩溃态；
- TaskBudget 全局总预算耗尽、累计未匹配度 / 不可量化步数触发全局熔断；任务终止，但组件本身没有销毁，属于业务任务死亡，不等于系统组件死亡。

> 关键区分：**业务任务死亡 ≠ 组件实体死亡；只有载体底层资源彻底失效才是死耦合。**

## 6｜架构优势、固有机理约束、条件触发隐患

### ✅架构优势

1. 分片两段式架构，区分并行规划段与 GUI 独占执行段；兼顾多任务提交能力，同时用`ExclusiveResource`隔离真实 GUI 操作冲突；
2. 梅花冲裁作为**唯一全局总仲裁收口**；资源、预算、风险、熔断、审计全部集中；下层只做上报、执行，禁止业务决策；
3. 完整可计算校验体系：普通 / COMPOSITE 复合校验 match_score；累计未匹配度、不可量化步数，三重熔断防御静默业务污染；
4. M0 手机裁剪记忆：双层 ui_fingerprint + 抽检；Activity 变动整批记忆复核；任务内部串行写队列规避同任务写冲突；禁止后台静默 LLM 抽取记忆；
5. TOCTOU 分层处理：实现层加固 stale 节点过滤；同时承认范式固有微小时差；针对不可重入分片命中 stale 节点增加强制熔断禁止重试；
6. MediaProjection 状态机，区分`RELEASED`/`REVOKED_BY_SYSTEM`转移语义；`state_version`防事件乱序重复；
7. 审计旁路与业务主链路严格分离；三级保证等级，如实写明外挂 App 进程被杀的现实丢失风险，不做虚假强承诺；
8. 完整六工况，每条工况附带检测与处置链路；严格三分法区分范式 / 实现 bug / 载体约束。

### 🔵固有机理约束

1. LLM 规划幻觉风险存在；即使多层校验，依然存在小概率幻觉记忆落库；
2. TOCTOU 采样‑执行存在微小时间窗口；加固只能降低概率，不能彻底消除；
3. 长任务错误累积可以被检测熔断，但**无法做到自动识别 + 自动修复，外挂版只做终止交还用户**；
4. M0 双层校验只能提高过期记忆检出概率；无法 100% 识别所有界面隐蔽变更；
5. 多任务并行规划依然可以产出冲突意图，只能靠执行段排队约束，无法完全消灭意图层面冲突。

### 🟡条件触发隐患（满足条件才显现，架构可降低触发概率）

1. Android 进程 LMK 随机查杀：分片中途内存状态丢失，只能回到分片完成快照续跑；
2. MediaProjection 被系统中途`REVOKED_BY_SYSTEM`回收；依赖状态机 + FROZEN 冻结任务，等待用户重新授权；
3. Android15 无障碍高频操作触发系统停用告警；分片 max_shard_step 与 pause 停顿节奏需要真机调优；
4. Android17 高级保护模式开启，外挂 App 直接失去无障碍权限，进入崩溃态；
5. COMPOSITE 子项权重、λ 衰减系数、熔断阈值、抽检比例配置不合理，会扭曲校验与防护效果；

> 以上配置参数属于业务实现层，架构仅定义计算语义，架构不固化常量。

## 7｜重构备选方案分级标记

### ✅上层封装｜外挂 App 版本，不改内核语义（设计已全部落实）

1. 资源拆分`ExclusiveResource / ShareableResource`，分片两段式生命周期；
2. MediaProjection 完整状态机，区分 RELEASED / REVOKED_BY_SYSTEM；state_version 全局序列号；主上报 + 探针兜底；
3. 机器可校验三元组，COMPOSITE 加权打分；区分可量化 / 不可量化目标；N 次不匹配 + 累计未匹配度 + 不可量化步数三重熔断；TaskBudget 分片结束扣减消耗；
4. TOCTOU 加固；`idempotent=false`分片命中 stale 节点强制熔断禁止重试；
5. M0 裁剪记忆双层失效校验；Activity 比对失败整批标记`verification_failed`；任务内部串行写队列；
6. 三层预算模型；网关全局唯一收口；执行层只上报风险无权业务决策；
7. 审计旁路三级保证等级，明确外挂版丢失风险；业务校验不走审计旁路；
8. 分片一等属性`idempotent`；补齐完整六工况全部处置链路。

### ⚠️改动内核｜远期 OS‑SystemService 原生版，外挂不碰

1. ROM 系统签名绕过 MediaProjection 新建会话弹窗；
2. 分片内部指令级断点；
3. 独立进程审计守护进程；
4. 系统层 GUI 资源抢占原语；
5. 记忆层引入 CAS 乐观锁，支持多任务并行修改同一条记忆。

### ⚪概念方案｜仅理论构想

1. GUI Agent 失败惯性自动自恢复机制。

# 附录 2｜故障注入测试用例集合

> 用途：验证整套架构设计工况触发、防护、熔断、处置链路；不针对具体实现代码；测试用例描述**触发条件、预期现象、系统预期行为**；阈值、系数均为业务配置项。

## 类别 A｜稳态用例（基准正向）

**A‑01 完整正常任务执行**

- 触发：用户下发合法任务；全部资源可用；每一步机器校验 match_score 接近 1；记忆指纹全部匹配；无异常事件。
- 预期现象：分片两段流转正常；逐分片完成；**每分片结束网关扣减 TaskBudget 实际消耗步数与耗时**；分片快照正常写入 M0 记忆；审计事件正常落盘；任务顺利完成。
- 预期行为：不触发任何熔断、冻结；任务正常结束。

## 类别 B｜偏移态用例

**B‑01 偶发控件识别偏差，未达到熔断阈值**

- 触发：单步识别轻微出错，match_score 小幅下降；未触发分片 N 次不匹配、累计未匹配度阈值。
- 预期现象：进入偏移态；分片继续运行；不熔断；依赖下一轮机器校验做修正。
- 预期行为：不终止任务；审计记录本次低分 match_score 事件。

**B‑02：ui_fingerprint 指纹命中匹配，但 Activity 内部页面实际 UI 发生变更，依靠第二层概率抽检检出异常**

- 触发：App 版本、Activity 名称未改变，但 Fragment / 网页内部 UI 改版；第一层`ui_fingerprint`校验通过；后台第二层概率抽检比对控件树哈希，检出不一致。
- 预期现象：偏移态风险；该 Activity 全部记忆标记`needs_reverification`送入复核队列；**不会触发视图分裂路径②处置逻辑**。
- 预期行为：记忆禁止直接供给规划；审计记录抽检检出界面变更事件。

## 类别 C｜冲突态用例

**C‑01 多任务并行规划产出互相冲突 GUI 意图**

- 触发：两个任务在阶段一（并行规划段）产出互斥操作意图；先后排队申请`ExclusiveResource`。
- 预期现象：冲突态告警；后到达任务进入资源等待队列；不会同时执行两套 GUI 操作。
- 预期行为：网关检测资源争抢，排队调度，不崩溃。

**C‑02 分片内部动作意图自相矛盾**

- 触发：LLM 产出分片意图内部动作互相矛盾；送入网关校验。
- 预期现象：冲突态；网关拦截，不下发分片执行。
- 预期行为：任务终止，交还用户；审计记录意图冲突事件。

## 类别 D｜视图分裂态专项用例

**D‑02 路径②：进程重启，持久记忆 ui_fingerprint 与当前真实 Activity 界面不匹配（第一层指纹校验直接检出不匹配）**

- 触发：任务中途 App 被杀重启；读取的持久记忆`ui_fingerprint`和当前运行 Activity 指纹不一致，第一层校验直接检出不匹配。
- 预期现象：视图分裂态‑路径②；网关触发界面真实性比对。
  - 子 D‑02‑A：比对通过 → **整批更新该 Activity 全部记忆 ui_fingerprint 元信息，恢复执行**；
  - 子 D‑02‑B：比对失败 → 该 Activity 全部记忆标记`verification_failed`，禁止供给规划层；网关熔断任务交还用户确认，必须人工确认才可重置标记。
- 预期行为：禁止只更新单条记忆；失败记忆打上禁用标记；审计记录视图分裂处置事件。

## 类别 E｜静默业务污染态专项（最高风险）

**E‑01 单分片每步勉强合格，累计未匹配度持续累积超限（普通可量化校验）**

- 触发：每一步 match_score 略小于 1，单分片没有触发 N 次不匹配；多分片叠加，累计未匹配度超过任务全局阈值。
- 预期现象：静默业务污染态；
- 预期行为：网关触发全局任务熔断终止；审计完整记录每一步 match_score、累计未匹配度。

**E‑02 COMPOSITE 复合校验，子项 marked_critical=true，整体 match_score 强制置 0**

- 触发：COMPOSITE 校验，其中一条子项标记`marked_critical=true`，其余子项分数很高。
- 预期现象：match_score 直接置 0；
- 预期行为：触发分片不匹配计数，按阈值逻辑处理；审计记录 critical 子项命中事件。

**E‑03 大量不可量化目标，不可量化步数独立统计超限**

- 触发：多条目标设置`requires_explicit_verification=true`，match_score=N/A；可量化校验全部合格，但不可量化步数到达全局上限。
- 预期现象：静默业务污染态风险；
- 预期行为：网关熔断任务；审计记录不可量化步数超限事件。

**E‑04 TOCTOU 范式固有窗口，动作命中错误对象，可加固环节未命中 stale 标记**

- 触发：控件读取时刻有效；动作执行瞬间页面跳转；没有触发 stale 节点标记；API 返回执行成功，但业务目标错误。
- 预期现象：静默业务污染态；无法在执行层直接拦截，只能靠上层机器校验 match_score 识别偏差。
- 预期行为：后续机器校验检出低分；达到阈值熔断；审计记录 match_score 低分事件；本用例属于范式固有风险，无手段 100% 前置拦截。

**E‑05 M0 记忆绕过双层校验，过期记忆直接供给规划层**

- 触发：抽检比例配置过低；过期记忆`ui_fingerprint`巧合匹配，未被抽检命中；过期记忆送入 LLM 规划。
- 预期现象：静默业务污染态；
- 预期行为：后续 GUI 校验检出偏差，触发熔断；审计记录记忆检索事件。

## 类别 F｜TOCTOU‑stale 节点专项（区分 idempotent 属性）

**F‑01 TOCTOU 检出 stale 节点，分片 idempotent=true（可重入）**

- 触发：执行层动作前重读，检出控件 stale 失效；分片标记可重入。
- 预期现象：不直接熔断；网关允许重新采集界面之后重试该分片；审计记录 stale 节点事件。

**F‑02 TOCTOU 检出 stale 节点，分片 idempotent=false（不可重入）高危用例**

- 触发：stale 节点命中；分片标记不可重入（发送消息、确认付款）。
- 预期现象：禁止重试；网关直接熔断全局任务；绝不允许重放分片。
- 预期行为：任务终止交还用户；审计重点标记高危不可重入分片被 stale 命中事件。

## 类别 G｜资源事件乱序、重复上报专项（state_version 版本管控）

**G‑01 采集层上报重复、旧 state_version 事件**

- 触发：IPC 抖动，旧版本资源状态事件重复回传给网关；state_version 不递增。
- 预期现象：网关直接丢弃版本号不增长的事件；不会发生重复冻结、重复告警；任务继续正常流转。

**G‑02 主上报通路完全丢失事件，靠健康探针兜底探测到资源失效 REVOKED_BY_SYSTEM**

- 触发：执行层主上报通路消息丢失；健康探针轮询探测发现 MediaProjection 已经被系统强制回收。
- 预期现象：网关将任务置 FROZEN 冻结；标记等待用户重新授权；不计入分片步数、分片超时。
- 预期行为：探针只做兜底；审计记录 “探针兜底检出资源失效，主上报丢失” 事件。

**G‑03 用户主动 RELEASED 释放会话**

- 触发：用户主动触发，MediaProjection 进入`RELEASED`状态。
- 预期现象：任务挂起等待用户重新发起任务；**不进入 FROZEN 冻结，不属于崩溃态**。
- 预期行为：不熔断任务；审计记录用户主动释放会话事件。

## 类别 H｜预算、状态机专项

**H‑01 MediaProjection 状态为 REQUESTING_USER_CONSENT，分片企图进入阶段二 GUI 执行**

- 触发：分片申请执行 GUI 操作；projection 状态还在等待用户弹窗授权。
- 预期现象：分片标记等待采集资源；**不计入 max_shard_step，不计入分片超时；不执行任何 GUI 动作**。

**H‑02 TaskBudget 全局总预算耗尽（全局步数 / 全局耗时到达上限）**

- 触发：任务全局预算被耗尽；多分片依次执行，每分片结束扣减消耗；下层分片还未结束。
- 预期现象：网关全局熔断终止后续分片；当前运行分片按分片内预算执行完毕后终止。
- 预期行为：全局任务终止；审计记录全局预算耗尽事件。

## 类别 I｜崩溃态（死工况）专项

**I‑01 ExclusiveResource 彻底不可获取；无障碍被 Android17 高级保护模式强制禁用**

- 触发：用户手动开启 Android17 高级保护模式，本 App 失去无障碍权限。
- 预期现象：崩溃态；整套编排链路失效；无本地自动恢复路径，需要用户人工干预。
- 预期行为：网关全部相关任务置 FROZEN；审计记录载体级死亡事件。

**I‑02 M0 记忆持久层 SQLite IO 故障**

- 触发：存储 IO 异常，读写记忆全部失败。
- 预期现象：崩溃态；任务无法生成分片快照；网关终止任务；审计尝试写入 Critical 级别事件（受存储故障影响可能无法落盘）。

## 类别 J｜审计旁路专项

**J‑01 Critical 事件触发，使用 Durable‑Commit 同步 fsync 提交**

- 触发：发生风险拦截、熔断；Critical 事件。
- 预期现象：执行同步 fsync 提交；网关 P99 延迟上升；

> 测试备注：外挂 App 架构约束，即便 Durable‑Commit，进程恰好在 fsync 中途被 LMK 杀死，依然存在丢失可能性，不视为 bug。

**J‑02 业务校验结果回传；校验结果不走审计旁路，走业务主链路**

- 触发：每一步机器校验完成；match_score 回传网关。
- 预期现象：校验结果在业务主链路流转；审计旁路仅记录事件摘要，**不承担业务判断输入来源**。
