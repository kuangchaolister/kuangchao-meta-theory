# KC‑TRSF‑JY 狂潮‑记忆变体 V1.1【封档版｜附录 C】

> 
> 定位：基于 KC‑TRSF 元架构 V1.1 的意图驱动型长期记忆子变体
> 目标：彻底废除传统 “外挂向量库 + 盲目召回” 缝合式 RAG 模式；实现**记忆提纯写入 → 记忆意图索引 → 遗忘与惯性演化 → 纯净上下文注入**端到端闭环。
>备注：本变体内部“六层记忆骨架库”对应作者提出的六层可控记忆体系；
>外部使用者如需复用记忆逻辑，六层分层的具体划分规则请自行参考对应元理论材料，本变体文档仅描述记忆系统的架构数据流、约束与契约，不重复展开六层内部分层细则。

> 配套关系：
> 
> 
> - 附录 A：KC‑TRSF‑SS V2.3（人主动找外部信息）
> - 附录 B：KC‑TRSF‑TJ V2.0（信息主动找人）
> - 附录 C：KC‑TRSF‑JY V1.1（模型 / 用户长期心智记忆演化）
> 遵从元架构全部公理：感知头子空间正交约束、状态读写分离、能量带熔断、`intent_contract`标准化契约。

## 一、全局双流模型拆解

### 1. 权限‑状态流

- **输入域**：当前会话流、多轮历史对话；**可选外部输入`intent_contract`**（来自 KC‑TRSF‑SS、KC‑TRSF‑TJ 输出，可将搜索、推荐解析得到的用户意图直接注入记忆系统）。
- **核心状态库**
  1. **六层记忆骨架库**：经微数据引擎提纯得到的高密度语义节点；剥离冗余语气、无效闲聊废话；原始对话文本做归档备查，不参与交叉匹配计算。
  2. **记忆时间戳与版本树**：记录每条记忆产生时间、最后命中时间、修改迭代版本，支持追溯、回滚。
  3. **偏好惯性池**：累积用户长期习惯、价值观、固定偏好权重；设置**永久保护标记位**，被标记的记忆条目禁止被老化衰减抹除。
  4. **会话临时工作区**：存放本轮会话第三方工具返回、外部不可信注入数据；仅会话生命周期有效，不持久化落盘至六层记忆骨架库。
- **输出域（两类输出）**
  1. 经过叠权收敛的纯净上下文片段：直接供给大模型做生成；
  2. 标准化`intent_contract`：JY 变体 KC‑MHA 感知层对外输出，可供给 SS、TJ 变体消费，实现双向双流互通。

### 2. 边界‑执行流

- **记忆演化引擎**：负责记忆的遗忘衰减、冲突消解；严格遵守状态读写分离规约。
- **检索调度器**：执行当前意图 Query 与记忆骨架的 Cross‑MHA 深度匹配。
- **污染隔离闸门**：阻断临时工作区不可信数据直接写入六层核心记忆骨架库。

## 二、核心模块架构（五大模块）

### 模块 1：记忆接入与感知层（Memory Gateway & KC‑MHA）

- 核心职责：接收会话对话流，同时可接收外部传入的`intent_contract`；通过 JY 变体实例化的四路专用路由头完成特征提取。

> 
> 元架构公理继承：JY 变体四路感知头训练阶段施加**子空间正交损失约束**；正交约束仅作用本感知层；下游匹配、演化叠权层允许因子合理耦合。

- JY 实例化四路路由头集合：事实实体、偏好因果、情绪状态、时间上下文。
- 输出：多路意图特征向量，生成本变体标准`intent_contract`。

### 模块 2：微引擎提纯写入层（Purification & Write）

- 核心职责：对当前会话内容做语义抽筋拔髓，剥离废话、语气修饰；输出高密度记忆骨架节点。
- 执行动作：
  1. 将对话原始内容拆解提纯为记忆骨架；打上时间戳、版本号；
  2. 经过污染隔离闸门校验：只有可信的内部会话记忆才允许写入六层记忆骨架库；
  3. 外部工具返回、第三方注入内容，仅放入**会话临时工作区**；临时工作区数据可参与本轮检索匹配，但**绝不写入长期记忆骨架库，不参与偏好惯性池累积演化**。

> 
> 示例：用户原话 “我今天非常生气地说他不想喝咖啡了” → 提纯骨架 `[偏好:拒绝咖啡，情绪:负面，时间:XX]`；原始完整聊天文本归档备查。
永久保护标记仅允许两类来源：① 用户显式记忆指令（例如 “请记住 XXX” 这类明确记忆指令）；② 系统底层硬编码元规则（安全红线、用户实名基础信息）；**禁止 AI 模型自主判断、随意给记忆条目打上永久保护标记。**

### 模块 3：记忆意图检索层（Cross‑MHA Retrieval）

> 
> 构件说明：复用元框架定义的`KC‑TRSF‑CrossMHA`算子；Query 侧为 KC‑MHA 输出的当前意图表征；K/V 侧不再是文档骨架，替换为**记忆骨架节点**。

- 核心职责：用户发起提问时，拒绝传统向量库单纯字面相似度召回。
- 执行动作：以当前意图矩阵作为 Query，与六层记忆骨架库 + 本轮临时工作区骨架做深度交叉注意力匹配，捞取意图真正相关历史记忆。

### 模块 4：状态演化与遗忘闸门（Evolution & Aging）

> 
> 严格遵从元架构强制规约：**状态信号比对计算属于只读操作；老化、权重更新、记忆条目权重修改为独立写入操作，二者物理分离。**

- 核心职责：记忆不是静态快照，完成记忆权重演化、冲突消解。
- 执行逻辑：
  1. **惯性叠权**：记忆条目被连续命中，则该条目权重加强；
  2. **异源爆发叠权**：识别用户发生真实偏好转变；设置最小观测窗口，禁止单次对话直接覆盖长期记忆；仅对发生突变的记忆维度做权重压制，其余历史偏好保留；
  3. **渐进式老化**：长期未被命中的记忆，权重逐步衰减，不会物理硬删除；
  4. **保护标记硬约束**：打上永久保护标记的记忆条目，完全跳过老化衰减流程，不会随时间失效。

### 模块 5：纯净注入网关（Clean Injection）

- 核心职责：把经过叠权筛选的记忆骨架，重组成格式规整的纯净上下文供给大模型；对外输出本变体的`intent_contract`契约。
- 铁律重申：会话临时工作区的外部不可信数据，仅参与本轮上下文组装；生命周期随会话结束销毁，禁止落盘长期记忆库。

## 三、工况判定与系统行为（遵从元架构运行契约）

1. **稳态**：意图清晰，记忆匹配无冲突；演化引擎正常执行只读比对 + 独立老化；输出干净上下文。
2. **偏移态（记忆冲突）**：新旧记忆出现部分矛盾，但未达到异源爆发阈值；仅累积冲突信号，不直接覆盖原有记忆权重。
3. **冲突态（异源记忆爆发）**：满足最小观测窗口条件，确认用户发生真实偏好改变；对突变维度执行异源爆发叠权，压制旧记忆权重，其余维度维持历史记忆。
4. **崩溃态**：检索 / 演化引擎超时、记忆库访问异常；故障降级**禁止回退旧范式（禁止直接投喂完整原始聊天记录、简易无过滤 RAG）**；返回有限安全上下文，上报监控。

> 
> 🔹通用运行契约：本变体定义能量带边界、检索超时熔断；故障降级严禁回退被替代的旧范式。

## 四、JY 变体固有取舍声明

1. 经过微引擎提纯的记忆骨架会丢弃原始对话细粒度措辞；原始完整对话文本归档备查，但不参与 Cross‑MHA 匹配计算。
2. 异源爆发存在误判风险；依靠最小观测窗口做防护，不能仅凭单次对话直接覆写长期记忆。
3. 记忆骨架库会持续产生新增条目；范式层面不做业务逻辑硬删除，依靠渐进老化做权重软抑制。工程兜底：长期极低权重且不带保护标记的冷记忆，支持在物理存储层执行冷归档分离，移出在线 Cross‑MHA 检索计算池，以此控制在线算力消耗；归档内容可按需恢复，不会彻底销毁记忆数据。
4. 临时工作区仅服务单次会话；外部数据即便本轮参与匹配，也不会沉淀进入用户长期心智记忆。
